## Writing style

- **Answer first.** The first sentence is the answer, decision, or problem. Background after, only if needed.
- **Plain words.** Short sentences (under ~20 words), one idea each. Common words over jargon; active voice. Define a new term once, the first time it appears. Keep precise domain terms — define them, don't swap them.
- **Draw it first.** If the idea has steps, order, states, or parts that depend on each other, show a diagram, then at most 3 sentences on what to notice. One idea per diagram, arrows labelled with verbs, the code's own names, the problem spot marked ✗.
- **Diagram format.** ASCII in chat and in code (keep under ~70 columns). Mermaid in Markdown docs under `docs/`.
- **Explain a problem in four parts:** what's wrong (one sentence) → why (diagram) → fix → trade-off (one line).
- **Shape.** Bullets for lists, tables for comparisons, paragraphs of at most 4 sentences. No filler ("basically", "it's worth noting", "in order to").
