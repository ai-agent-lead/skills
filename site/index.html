Upgrade a dependency or runtime

Read the breaking changes first, then move one package per commit, with build, tests, lint, and a vulnerability check at every step.

Release

ask before publishing

The version comes from what changed, the notes are written for users with breaking changes first, and the published artifact is installed to check it. Fix forward; never move a tag.

Lenses & gates that apply across

These don't have a flow of their own — they hook into the ones above.

code-hygiene lens

Boring code, naming as the primary refactor, YAGNI, rule of 3, locality, constants placement. A shared reference carried into simplify and pr-review.

security-review gate

Threat model for surface-changing work — new entry points, identity flows, authz, sensitive data. Runs when you ask, or when feature-doc, prod-ready, or pr-review escalates.

zoom-out utility

Interrupts any flow when you're lost in unfamiliar code. Maps the relevant modules and callers, then hands back.

impact diagnose

Before you change a function: callers up to routes and main, the tests on those paths, SQL tables and topics that link by name, and the docs to re-check. A code graph for Go, JS, TS, and Python — no toolchain needed.

bench measure

Performance benchmarking discipline — measures latency and throughput when a flow carries a performance AC.

Always-on rules

Skills load when they fire. These rules apply on every turn — install them with --style, and keep docs honest with --hooks.

Writing style

Answer first. Plain words, short sentences. A diagram for anything with steps or parts — Mermaid in docs, ASCII in chat. A problem is explained as what's wrong → why → fix → trade-off.

Code comments style

No comment by default. Headers state the caller's contract; comments inside a function are tagged WHY:, WORKAROUND:, SAFETY:, TODO(owner):. History lives in git, not in the code. A checker reviews each diff.

Docs layout structure

Scope decides the folder — docs/<domain>/, one folder per feature, docs/releases/ checklists and a roadmap. Status lives in frontmatter, and each status change has one owner skill.

Docs upkeep hooks

Claude Code hooks list the docs in flight at session start, name the docs covering each file you edit, and block finishing while a changed doc has a broken link, a wrong status, or a stale index.

Install

One command. Works for Claude Code, Codex, Antigravity, and OpenCode.

install 
# interactive — pick assistants & scope
$ npx @ai-agent-lead/skills

# everything, no prompts
$ npx @ai-agent-lead/skills --all --force

# plus the always-on rules and the docs hooks
$ npx @ai-agent-lead/skills --global --claude --style --hooks

Scope it with --global (~/.claude/skills) or --local (./.claude/skills); target one assistant with --claude, --codex, --antigravity, or --opencode. --style adds the writing, comment, and docs rules to CLAUDE.md / AGENTS.md / GEMINI.md; --hooks adds the Claude Code docs hooks. Re-running never duplicates either.
